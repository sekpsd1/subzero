# Admin products — SYS-02 catalog
Updated: 2026-10-05 (Asia/Bangkok). Scope: products, brands, categories and images only.

## Behavior and permissions
- `/admin/products`: real MySQL list, model/name/slug search, brand/category/status/deleted filters; 20 rows per page with stable sorting and server-side counts/pagination.
- `/admin/products/new` and `/admin/products/[id]`: model/name/slug, brand/category, series/type/width/finish, description, features (one per line), specifications (JSON text key/value object), Draft/Active/Archived.
- `/admin/catalog`: brand and category create/edit; subcategory parents; cycle and brand ancestry checks. Used brands/categories cannot be removed, including references from deleted products.
- ADMIN and STAFF: read/create/edit products, change status, upload/remove/reorder images and edit alt; create/edit brands/categories. ADMIN only: soft delete/restore products and delete unused brands/categories. Restore always returns Draft. No hard-delete product endpoint. Both roles are read from the database session by existing requirePage/requireApi helpers; submitted role/private fields are ignored.
- Every mutation repeats session/role and configured exact Origin checks via requireApi. Product/image edits reject stale updatedAt versions. Product row locks serialize product/image changes. Mutations and audit entries commit in one transaction. Audit contains action/entity/ID only, never bodies, credentials or raw image bytes.
- Server validation bounds text/JSON/body size, validates foreign keys/status, checks category ancestry, rejects model/slug uniqueness conflicts (including deleted products) and returns meaningful 4xx errors. Database/config failures return 503, never a mock success.

## Images and storage
- Default persistent directory: `.product-media` in application root, outside public; optional absolute `PRODUCT_MEDIA_DIR` must also be private and persist across releases. Directory 0700, files 0600 on Linux. Keep this directory in host backups; it is excluded from Git and build source uploads.
- One upload/request, JPEG/PNG/WebP only, 5 MiB/file, 6 MiB multipart request, 24 million decoded pixels, maximum side 8000 px, no animation; up to 20 images/product. Server decodes with sharp, verifies format against MIME and re-encodes WebP with orientation correction and metadata removal. Original filenames/paths are never retained.
- Managed image URL `/api/product-images/[id]` serves only images linked to an existing product; public access requires Active + not deleted. Other states require a current ADMIN/STAFF session. Cache private/no-store, Vary Cookie, nosniff. No Next image proxy for authenticated previews.
- Remove unlinks the ProductImage record immediately. Bytes remain private for recovery/retention; no route can serve orphan bytes. Upload failures remove their own unlinked file. Physical retention/garbage collection is not automated and needs an explicit retention policy before long-term operation.

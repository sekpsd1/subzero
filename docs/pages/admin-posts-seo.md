# Admin posts and SEO — SYS-02 CMS
Updated: 2026-10-05 (Asia/Bangkok). Status: deployed to staging and verified within scope.

## Implemented behavior
- /admin/posts uses Prisma/MySQL, title/slug search, Draft/Published/Archived and current/deleted filters, 20-row server pagination, stable updatedAt/id sorting and consistent count/list transactions. Database failures are errors, never sample-success responses.
- /admin/posts/new and /admin/posts/[id] edit title, unique slug, excerpt, HTML content, category and up to 30 unique tags. HTML source editor includes paragraph/heading/bold/italic/quote buttons. Content is limited to 120000 characters; JSON requests are bounded at 256 KiB.
- Server-side DOMPurify 3.4.16 with jsdom 27.4.0 allows only editorial paragraph/headings/lists/emphasis/links. Scripts, embeds, SVG, images, CSS and event handlers are removed. Link schemes restricted to http/https/mailto, protocol-relative links denied. Preview sanitizes again to protect against legacy unsanitized rows. [Maintainer documentation](https://github.com/cure53/DOMPurify).
- ADMIN/STAFF create/edit Draft and Archived posts and create/edit categories/tags. ADMIN alone publishes/unpublishes, saves already-Published content, changes Published covers, soft-deletes/restores posts, and deletes unused taxonomy. Published content is read-only for STAFF to prevent saving from acting as publication. This implementation does not include a separate pending-revision approval workflow.
- Publishing stamps publishedAt server-side. Draft/Archived/deleted/restore clear publishedAt. Restore always returns Draft. There is no public hard-delete post API and no client-controlled author/deletedAt/publication date.
- Every mutation uses existing requireApi session/role and exact Origin checks. Post/content/cover/lifecycle mutations lock the Post row, require the submitted updatedAt, and advance a monotonic timestamp. Writes and body-free audit records commit atomically. Taxonomy changes use Serializable transactions, duplicate name/slug checks, previous name/slug checks for stale edits/deletes, and protect relationships including deleted posts.
- /admin/posts/taxonomy manages categories and tags. /admin/posts/[id]/preview requires requirePage and the admin proxy. Preview and APIs use no-store; preview is noindex/nofollow. No unauthenticated Draft URL or token-link preview channel is added.
- SEO stores title, description, validated absolute HTTPS canonical, Open Graph title/description/image, four supported index/follow robots combinations, and sitemapVisible. Managed cover populates OG image. Private preview displays saved SEO. sitemapPosts() provides Published/non-deleted/past-publication/visible/non-noindex selection for the separate public integration task.

## Cover storage
- Reuses the catalog decoder/limits as an isolated implementation; existing product media sources and ProductImage storage are untouched. Post cover uses existing Media rows and Post.coverImage, so no schema change or migration is required.
- Private persistent .post-media under app root, directories 0700/files 0600 on Linux. New paths are Git-ignored. Include this directory in hosting backups and retain across releases.
- JPEG/PNG/WebP only, 5 MiB/file and 6 MiB multipart body, maximum 24 million decoded pixels/8000 px side, no animation. sharp fully decodes, verifies MIME against detected format, rotates and re-encodes WebP, discarding metadata/original names. Failed transactions remove their own unlinked file.
- /api/post-images/[id] serves only the current linked cover. Public access requires Published, not deleted, non-null publishedAt <= now. Other states require an existing admin session. Private/no-store, Vary Cookie, nosniff. Direct img is intentional for authenticated media; no Next optimization proxy.
- Removing/replacing a cover unlinks it immediately; retained Media rows/private bytes cannot be served unless still linked. Physical orphan retention/garbage collection is not automated.

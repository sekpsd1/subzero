## Scope and semantics
- /admin/inventory: real Prisma/MySQL list, model/name search, status and include-deleted filters, server pagination (20), stable model/id order, consistent count/list and global totals. Global totals include inventory attached to deleted products. Product without Inventory is explicitly unrecorded/zero; listing does not create rows or seed sample stock.
- Total = physical on-hand including reservations. Available = total minus reserved. Receive and adjust-up increase total. Adjust-down reduces available only (never silently removes reservations). Reserve increases reserved. Release decreases reserved. Sell-reserved decreases both total and reserved. Sell-available decreases total only. Every operation requires a positive integer amount and a reason, maximum 1000 characters. Absolute balance overwrite and ambiguous SOLD input are not supported.
- ADMIN mutates; STAFF reads only. Existing requirePage/requireApi enforce current database roles and exact Origin. Transaction rechecks and locks User/AdminSession, expiry/revocation and ADMIN role before changes.
- Product FOR UPDATE serializes stock operations even when Inventory does not exist yet, and coordinates with existing product lifecycle locks. Inventory is locked explicitly too. ReadCommitted interactive transaction commits balance, immutable StockMovement and existing body-free AuditLog together. All server calculations enforce quantity >= 0, reserved >= 0, reserved <= quantity and signed-Int limits.
- Unique persisted idempotencyKey stores request hash and actor. Same key/payload/actor replays original movement; changed payload/actor conflicts. Client blocks simultaneous submit and preserves pending key and values in sessionStorage before dispatch, including reload/network retry. Never discard a pending unknown request to initiate a different operation. Replay response describes original movement; use refreshed detail for current balance.
- Movement captures actor ID/name snapshot, server timestamp, explicit operation, positive units, note, total/reserved before and after, and optional compensationForId. Legacy rows retain unknown nullable metadata; no invented history/backfill. History has server pagination and no edit/delete API. Additive DB triggers reject UPDATE/DELETE; corrections append new, reasoned movements referencing an existing movement for the same product.
- Deleted products remain readable in inventory/history and retain balances; restore in existing catalog before mutation. No public stock/history API, public-source redesign, payment/order or multiple-warehouse feature.
